# Plan: multiple imputation + LSPIM (`MI_LSPIM`)

Agreed 2026-10-20 (grilling session). Branch `feature/mi-lspim` off `main`, one conventional
commit per item, PR description drafted at the end. The user starts the implementation and
merges.

Goal: a new analysis method `MI_LSPIM` that imputes the missing outcomes with the MI-CbC
imputation model, fits LSPIM (engine `pgee_fw`) on each completed dataset, pools `beta` and `V`
with Rubin's rules, and runs the LSPIM Holm test on the pooled values with a t reference
(Barnard-Rubin df, `nu_com = N - 2`).

## Decisions

- **Where to pool.** At the level of `beta` and `V` (vector Rubin's rules), before the Holm
  step. Not on p-values, not on Holm decisions, not by stacking imputations.
- **Refactor of `fit_lspim()`** ([lspim.R](../scripts/simulation/lspim.R)), result-neutral:
  - `lspim_estimate(dat, engine)`: input validation, pair construction (pair order unchanged,
    it fixes the geessbin floating-point sums), pseudo-scores, design, PGEE/GEE fit, and the
    non-finite-beta check. Returns `beta`, `V_raw`, `converged`, `treatment_terms`.
  - `lspim_holm_test(beta, V, alpha, df)`: PSD check and `nearest_psd()` repair with the
    existing warning, deviation contrasts from `make_deviation_from_mean_l()`, contrast
    estimates `L beta` and SEs `sqrt(diag(L V L'))`, raw p-values `2 * pt(-|t|, df)`,
    `p.adjust(method = "holm")`, and the existing finite-p check. Returns the same list as the
    current `fit` (`beta`, `V`, `Holm_p`, `interaction_rejected`, `interaction_alpha`,
    `interaction_test_procedure`). `df` may be a scalar or one value per contrast.
  - `fit_lspim()` keeps its signature and return value: it wraps `lspim_estimate()` +
    `lspim_holm_test(df = Inf)` in the existing warning/error capture. `pt(., Inf)` is `pnorm`,
    which replaces `multcomp::glht(parm(beta, V))` (df = 0, normal).
  - Gate: the LSPIM goldens must pass unchanged. If they do not, LSPIM keeps the current
    `multcomp::glht` call and only `MI_LSPIM` uses the manual t-based Holm code. Report to the
    user which path was taken.
  - If `multcomp` is no longer used anywhere, remove its `requireNamespace()` check and note
    (do not edit) whether `renv.lock` / `dependencies.R` could drop it.
- **Generalise `pool_rubin()`** ([analysis_layer.R](../scripts/simulation/analysis_layer.R)):
  a shared core taking a list of m >= 2 coefficient vectors and m covariance matrices, returning
  `beta_bar`, `U_bar` (mean of the V's), `B` (sample covariance of the coefficient vectors,
  denominator m - 1), `T = U_bar + (1 + 1/m) B`, and `m`. `pool_rubin(estimates_list, nu_com)`
  keeps its interface and output names for CbC (diagonal V built from `se_betaK^2`; variance
  components still averaged). Drift in `multiple_imputation` results is accepted within the
  golden tolerance only.
- **Imputation.** Reuse `impute_data()` with the `multiple_imputation` default `impute_args`
  (`set_impute_args(method_y = "2l.pmm")`: `trt_time` in the imputation model, m = 3,
  maxit = 10). Data are prepared with `prepare_analysis_data(type = "multiple_imputation")`
  (NA rows kept). With the shared per-replicate analysis RNG substream, `MI_LSPIM` fits the same
  imputed datasets as `multiple_imputation` (common random numbers; intended).
- **Pooled inference.** Per imputation `lspim_estimate(engine = "pgee_fw")`; pool `beta` and
  `V_raw` with the generalised core; PSD check and repair once, on the pooled `T` only (not per
  imputation). Per Holm contrast `l`: `lambda_l = (1 + 1/m) l'Bl / l'Tl`, df from the existing
  `barnard_rubin_df(lambda_l, m, nu_com)` with `nu_com = N - 2` (N = number of subjects in the
  replicate), then `lspim_holm_test(beta_bar, T, alpha, df = <per-contrast df>)`. Decide whether
  lambda uses `T` before or after the PSD repair and document it in the roxygen (preferred:
  before, the repair only affects the test).
- **Failures and convergence** (mirror `fit_mi_closed_form()`): if the imputation or any of the
  m LSPIM fits errors, the replicate fails, error message prefixed `"imputation k: "`; no
  pooling over fewer fits. `converged = TRUE` only if all m pgee_fw fits converged.
  `singular = FALSE` as for LSPIM.
- **Naming.** Method key `MI_LSPIM`, engine label `mice_pgee_fw`. Functions `fit_mi_lspim()`,
  `analyze_mi_lspim()` (with `rng_state` as `analyze_mi_closed_form()`, and the same 2l.pmm
  availability check), `analyze_generated_data_mi_lspim()`.
- **Engine.** `pgee_fw` only; no `lspim_engine` config key for `MI_LSPIM`.
- **Registry.** New entry `MI_LSPIM` in `build_analysis_registry()` with
  `default_config = list(impute_args = set_impute_args(method_y = "2l.pmm"))`. **No n gate**
  (no `applies_to`). Not added to the `run_all.R` defaults or configs.
- **Result row.** Same fields as LSPIM via `extract_lspim_results(method = "MI_LSPIM",
  engine = "mice_pgee_fw")`: interaction decision, alpha, test procedure (e.g. "Holm-adjusted
  treatment-effect deviations, MI (Barnard-Rubin t)"). No new columns, no aggregation changes.
- **Statistical caveat to keep in mind** (no action): with m = 3 the Barnard-Rubin df can be
  small when lambda is large, so `MI_LSPIM` may be conservative. Larger m is already a backlog
  item for `multiple_imputation`.

## Tests

- **Pooling unit tests:** the generalised core against hand-computed `beta_bar`, `U_bar`, `B`,
  `T` on small inputs (m = 2 and 3, p = 2); the CbC `pool_rubin()` wrapper returns the same names
  and (within 1e-12) values as before on a fixed input.
- **Reduction test:** m identical completed datasets (B = 0): `beta_bar` and `T` equal LSPIM's
  `beta` and `V` on that dataset; each contrast df equals
  `nu_obs = (N - 1) / (N + 1) * (N - 2)`.
- **Failure paths:** one imputation's fit errors -> failure row with `"imputation k: "` prefix;
  one non-converged fit -> `converged = FALSE`; a non-PSD pooled `T` -> the PSD warning in
  `warning_message`. Stub `lspim_estimate()` / `impute_data()` as existing tests stub
  `fit_lspim_gee()`.
- **Golden:** `MI_LSPIM` rows at a small n in the golden pipeline.
- Holm step: `lspim_holm_test(df = Inf)` equals the old glht result on a fixed input (keeps the
  gate checkable after `multcomp` is gone).

## Status

Implemented 2026-10-20 (commits d13cc89, dd421e2, 868b846, 7d3ff18). LSPIM kept the manual
t-based Holm path (df = Inf): Holm p-values differ from `multcomp::glht` by at most 4.4e-16, all
else identical, goldens unchanged. `multcomp` is no longer used by the code but is still in
`renv.lock` (could be dropped; `dependencies.R` does not list it). Pre-existing on `main`: 17 failing expectations
in `test-run-all-grid.R` (grid in `run_all.R` changed, test not updated).

Smoke run 2026-10-20 (null, half_missing, 6 visits, 50 sims, n = 10/20/50): MI_LSPIM had no
failures or non-convergence; rejection rates 0.02 / 0.02 / 0.00 (LSPIM 0.10 / 0.06 / 0.06, LSPIM
failed 10/50 at n = 10); pooled-T PSD repair in 27/50 replicates at n = 10, 1/50 at n = 20;
about 0.7-1 s per replicate (mostly mice).
